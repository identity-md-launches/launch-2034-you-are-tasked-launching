This project supplies a one-use application contract, ERC20TLaunch, and a static website. The application is deployed through the project handoff. The designated owner then uses it to create the ERC20T token and its IMD pool in a single transaction through the existing factory. No mainnet transaction was broadcast while building this project.

Starting price

The suggested price is 0.00000054054054054 IMD / ERC20T. Multiplying by one billion gives 540.54054054 IMD fully diluted value. At the historical $5.55/IMD observation on 16 October 2026, that is approximately $3,000. This is an indicative spot-price calculation, not an oracle, guarantee, or funded reserve. The owner must review current market conditions. The factory rounds the actual opening price to a usable tick.

What the application enforces

Only the explicit owner can launch, on chain 1, once. The integration’s pinned dependencies must match their tested runtime fingerprints, and the IMD-to-ETH fee-conversion route must match the tested configuration. The launch verifies metadata, total supply, allocation conservation, both recipients, tax parameters, the pool key and the position NFT. A failed check reverts creation and pool initialization together. The application accepts no ETH or user token approvals.

Single-sided liquidity needs no IMD deposit. The existing token implementation mints its position NFT to its fixed burn address 0x000000000000000000000000000000000000dEaD. This is the protocol’s onchain behavior, not a substitute owner address. The application checks that recipient, nonzero liquidity, and the matching pool. Integer rounding can leave at most 0.000001 ERC20T in the token contract; the observed default launch left just 1,010 token-wei. The owner allocation remains exactly 50 million.

“First” must be proved

The factory’s first clone already existed at block 26,208,319. Its address is 0xBBe9d1EcBae3D811642f3DFFDF8bC5Ae8ea4514f. The application supports a first-only guard, which will reject this occupied slot. An owner may explicitly accept a later launch. The website scans every factory creation event from its deployment block, counts successful creations in chain order, and derives an exact ordinal from the actual launch receipt. Simulation does not reserve an address or an ordinal.

Ownership and trust

The token retains the existing infrastructure’s owner controls. After the launch decay completes, its owner can change the resting tax within the implementation’s 30–500 bps limits, change fee recipients, manage distributors, and transfer token ownership. The website displays current onchain token tax and recipients after launch. The hook converts collected fees to native ETH through its configured IMD/ETH pool and takes its 15 bps protocol share from the token tax. The protocol receives floor(convertedTaxETH × 15 / currentTaxBps); at a 1% resting tax this is 15% of converted fees. The owner receives the rest. The conversion pool has a 1% pool fee, and price impact also affects payouts. The existing hook’s owner controls its protocol recipient and conversion configuration. The token’s owner does not control that protocol fee destination. The application itself has no upgrade, withdrawal, arbitrary-call or token-management function.

The factory and token implementation were unverified on the explorer during preparation. Compatibility was checked using their actual mainnet bytecode and a read-only launch simulation. The offline test fixture captures the dependencies and required storage at block 26,208,519. Tests exercise a real factory launch, both currency orders, lock checks, tax decay, real buy/sell fee settlement, allocation conservation and failure rollback. This is not an independent audit of Adam’s infrastructure or Uniswap.

Operator handoff

  1. Deploy ERC20TLaunch(address owner_) with the designated owner. Its constructor is nonpayable and makes no external calls.
  2. Set controller in site/deployment.json to the confirmed application address, or paste that address into the app. Do not substitute the factory or a token address.
  3. Review the current IMD price, complete factory history, owner wallet, and launch terms. Use the owner wallet to review and simulate.
  4. Confirm the single application transaction. Wait for a successful receipt; do not retry an uncertain submission without checking chain state.
  5. Refresh the site. Verify the emitted token address, pool ID, position NFT, factory ordinal and transaction hash. Trading links unlock after 12 confirmations.
  6. Publish the confirmed evidence. Monitor the token’s owner settings and fee collection through the existing infrastructure.

Local, self-contained site

Serve the site/ directory over HTTP. Fonts, JavaScript, the Ethereum client and ABI are included. No installation or CDN is required. Only explicit live chain reads use the public Ethereum RPC; wallet signing uses the injected wallet provider. No keys or signing credentials are stored in this site.
